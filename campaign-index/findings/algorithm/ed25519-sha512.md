# Algorithm: Ed25519 + SHA-512 (cert-side)

**Confirmed**: cycle ~580, 2026-05-02

## Helper PC → primitive map
| PC (lib offset) | Primitive |
|---|---|
| 0x2863f8 | SHA-512 update(ctx, ptr, len) |
| 0x284e3c | SHA-512 finalize(ctx, out) |
| 0x285500 | SHA-512 compress (block) |
| 0x2d6538 | Ed25519 sc_reduce (64B → canonical 32B mod L) |
| 0x2e08bc | Ed25519 signed-window slide (256 signed digits) |
| 0x2def54 | Ed25519 fe_mul (field multiply, plain — no precomp table) |
| 0x2df420 | Ed25519 ref10 base-point scalarmult (ge_precomp[32][8] table at 0x352ba0, 0x3c0 stride — stock layout) |

## SHA-512 ctx layout
- `ctx+0x00..0x38` — 8 chaining u64s
- `ctx+0x40/0x48` — bit count
- `ctx+0x50..0xcf` — 128B block buffer
- `ctx+0xd0` — buffered byte count

## Implications
- Rust port can use `sha2::Sha512` and `ed25519-dalek` — no custom primitives needed
- The campaign-final's earlier "CRC32-IEEE" / "FFT/butterfly" interpretation was wrong; that's just Ed25519 scalar multiplication

## Phase 1 algorithm (cert frag1, fully decoded)
1. Take 64B block at `sp+0x968`
2. Single-block SHA-256 compress
3. Byteswap32 each output word
4. Take digest[4..28] (24 bytes = 48 hex chars)

Reproducer: `cert-rust-repro/src/bin/cert_rust_repro.rs` — verified producing `641d96f7...` from captured no-bypass donor session.
